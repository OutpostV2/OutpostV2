# /api/v1 compatibility contract

The frozen machine-readable snapshot is at backend-js/tests/contracts/api-v1.contract.json. It was generated from create_app(...).openapi() with inert local settings; no HTTP request or database connection was made. It captures 30 operations, 39 schemas, parameters, request bodies, declared statuses, and security. Twelve operations are public; 18 require an Authorization: Bearer header. Public refresh uses the outpost_refresh cookie. The snapshot includes review and live-learning routes used by the current Node API.

OpenAPI has two runtime gaps. GET /api/v1/auth/google/authorize responds with a 302 redirect and no-store/no-cache headers, although OpenAPI lists 200. For 422 responses, the installed handler returns the common error envelope {"error":{"code","message","details"?,"request_id"?}}, while OpenAPI lists HTTPValidationError. Validation details contain only loc and type; request bodies are never echoed. Other application errors share the envelope with codes such as unauthorized, forbidden, not_found, conflict, rate_limited, and not_ready. The request-ID middleware echoes a valid UUID from X-Request-ID or generates one and returns it in that header.

## Session and identity behavior

- Password login, phone verification, and Google callback return a bearer access token and set an outpost_refresh cookie with Secure, HttpOnly, SameSite=strict, Path=/api/v1/auth, and a 30-day maximum age. The refresh value does not appear in JSON. Access tokens use HS256, issuer outpost, audience outpost-api, and a 900-second lifetime. Protected routes check live user and session state.
- Refresh rotates the cookie and session. Reusing an ancestor refresh token returns 401 and revokes that token family. Session listing shows only usable leaf sessions for the caller. Session revocation is owner scoped, returns 404 for missing or foreign IDs, and is idempotent for an owned session. Logout revokes the current session; logout-all revokes the caller's sessions. Cookie deletion uses the same path and security attributes.
- Registration normalizes login identifiers, stores Argon2 hashes, rejects duplicates with 409, and never echoes passwords. Failed login returns a generic 401. Email-verification and forgot-password requests return 202 without revealing account existence or delivery success. Verification and reset tokens are stored as hashes, expire, and are single use. Password reset clears the refresh cookie, revokes sessions, and requires a new login.
- Phone OTP requests return 202 on normal and masked delivery outcomes; rate limiting can return 429. Verification consumes a challenge once, bounds wrong attempts, and returns a generic 401 for invalid or expired codes. Google authorization state is single use; callback replay returns 401. Google identity is tied to the provider subject, and an email collision does not silently link accounts.

## Review and live-learning behavior

- Review overview is authenticated. Student completion persists per user; another student does not see it. Unknown topic keys return 404. Coordinators can see the coordinator view but get 403 when trying to change review progress. The scenario content and peer learners are illustrative fixtures.
- Organization creation requires a coordinator. Roadmap and cohort operations require active organization ownership; an unrelated coordinator gets 403. A roadmap version from another organization cannot be used to create a cohort and returns 404. Joining requires a student and valid invite code; an unknown code returns 404, while repeating a join succeeds. Progress is scoped to joined cohorts and assigned topics. Cohort progress is limited to authorized organization members.

These points were derived from the retired Python integration tests (available in Git history), particularly the session, login, refresh, OTP, Google, review, and live-learning workflow tests. OpenAPI declares success and validation statuses only; the conditional 400/401/403/404/409/429/503 cases above are runtime behavior established by handlers and tests. Current Node route tests enforce the frozen operation surface.
